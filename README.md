# Outbreak Vulnerability Sentinel

An agent that detects **blind spots in global disease surveillance** by
cross-referencing three signals per region:

1. **Official survey data** — slow, authoritative, goes stale
2. **Hospital admissions data** — fast-moving proxy signal
3. **Resource allocation data** — funding / staff / vaccine stock

The agent flags regions where survey data is stale **AND** admissions trends
suggest an emerging risk **AND** resources are inadequate, writes a justified
vulnerability assessment back into DataHub as an annotation, and serves the
results through a React web app.

Built for the **Build with DataHub: The Agent Hackathon**.

---

## Architecture

```
DataHub Instance  ◄────►  MCP Server
                             │
                             ▼
                    FastAPI Backend  ──►  data/latest_report.json
                    (agent orchestrator,      (JSON persistence)
                     Gemini reasoning,
                     REST endpoints)
                             │  JSON / REST
                             ▼
                    TypeScript React frontend
                    (regions list + detail view)
```

- **Backend**: Python + FastAPI (`backend/`)
- **Reasoning**: Gemini API via the `google-genai` SDK (`backend/app/agent/reasoning.py`)
- **Data platform**: DataHub via MCP Server — **currently stubbed**
- **Persistence**: a single JSON file, `data/latest_report.json`
- **Frontend**: React + TypeScript, built with Vite, styled with Tailwind CSS (`frontend/`)

## Backend setup

Requires Python 3.11+.

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate        # Windows (use `source .venv/bin/activate` on macOS/Linux)
pip install -r requirements.txt
copy .env.example .env        # Windows (use `cp` on macOS/Linux)
# then edit .env and set GEMINI_API_KEY
```

Run the API (from the `backend/` directory):

```bash
uvicorn app.main:app --reload --port 8000
```

Interactive docs: <http://localhost:8000/docs>

Run the tests (from the `backend/` directory):

```bash
pytest
```

## Frontend setup

Requires Node.js 18+.

```bash
cd frontend
npm install
npm run dev
```

Open <http://localhost:5173>. The Vite dev server proxies `/agent`, `/regions`
and `/health` to the backend at `http://localhost:8000` (see
`frontend/vite.config.ts`). If your backend runs elsewhere, set `VITE_API_BASE`
(e.g. in a `frontend/.env` file) or adjust the proxy target.

Build for production:

```bash
npm run build
```

## Backend API contract

| Endpoint                 | Description                                                              |
| ------------------------ | ------------------------------------------------------------------------ |
| `POST /agent/run`        | Trigger the agent loop as a background task. Returns `202` + `AgentRunStatus`. |
| `GET /agent/status`      | Current `AgentRunStatus` (`idle` / `running` / `complete` / `error`).     |
| `GET /regions/vulnerable`| Latest `VulnerableRegionsReport`. Filters: `?min_level=Low\|Moderate\|High` (default `Moderate`), `?country=...`. |
| `GET /regions/{region_id}` | Single `RegionAssessment`, `404` if not found.                          |
| `GET /health`            | Liveness check.                                                          |

## Data schema

The schema below is identical across the backend (Pydantic), the frontend
(`frontend/src/types/region.ts`), and the examples (`examples/`).

```
RegionAssessment:
{
  "region": string,            // e.g. "Region-West-Kenya"
  "country": string,           // e.g. "Kenya"
  "vulnerability_level": "Low" | "Moderate" | "High",
  "justification": string,     // 1-3 sentences, plain language
  "confidence": "Low" | "Medium" | "High",
  "key_signals": string[],     // e.g. ["survey stale 42 days", "admissions +38% over 14 days"]
  "days_stale": integer,
  "flagged_at": string         // ISO 8601 timestamp
}

VulnerableRegionsReport:
{
  "generated_at": string,                       // ISO 8601
  "total_regions_evaluated": integer,
  "total_flagged": integer,
  "regions": RegionAssessment[]                 // sorted: level desc, then days_stale desc
}

AgentRunStatus:
{
  "status": "idle" | "running" | "complete" | "error",
  "started_at": string | null,
  "completed_at": string | null,
  "error_message": string | null
}
```

## Synthetic data

Generate the three CSVs used by the agent (no network needed):

```bash
python data/ingestion/generate_synthetic_data.py
# writes data/synthetic/{regional_survey_data,hospital_admissions,resource_allocation}.csv
```

`region` is the consistent join key across all three datasets. The generator
models a realistic "blind spot": a few regions with stale surveys, rising
admissions, and below-average resources.

## DataHub integration (stubbed)

DataHub is the context layer for this project, but the real MCP calls are **not
implemented yet** — `backend/app/agent/datahub_client.py` is a stub: every
method raises `NotImplementedError` and its docstring describes the exact MCP
call it should eventually make. The rest of the stack (orchestrator, routes,
schemas, frontend, tests) works against the `DataHubClient` **interface**, so no
other changes are needed once the stubs are filled in.

Planned integration points:

- `get_regions` / `get_freshness` / `get_recent_values` / `get_values` — read
  survey, admissions, and resource data from DataHub via the MCP server.
- `write_annotation` — write each vulnerability assessment back to DataHub as a
  discoverable annotation on the region's dataset entity.
- `data/ingestion/load_to_datahub.py` — ingest the synthetic CSVs into DataHub
  as dataset entities with freshness metadata (also stubbed).

Until DataHub is running, an agent run will fail at the first
`DataHubClient` call and the run status will be `error`. To demo the full loop
before DataHub is up, see the hand-written example report in
`examples/sample_vulnerable_regions_report.json`.

## Model note

The scaffold fixed the Gemini model as `gemini-2.5-pro`. It is still
operational but was deprecated in June 2026 (shutdown planned for 16 Oct 2026).
The official replacement is `gemini-3.1-pro-preview` — set `GEMINI_MODEL` in
`backend/.env` to migrate.
